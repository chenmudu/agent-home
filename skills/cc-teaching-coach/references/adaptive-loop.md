# 自适应循环

这份文件展开 `SKILL.md` 的主循环：每一轮怎么探测、怎么讲、怎么让用户做、怎么根据反馈改下一步。

## 0. 目标契约

开始前把模糊目标变成可验证句：

```text
学会 = 能 <在什么场景下> <完成什么任务> <达到什么标准>
```

例：

- “学会 = 能独立读一个 benchmark 表，判断某模型在长上下文上的优势是否可信。”
- “学会 = 能给一个报错定位到 `file:line`，提出最小修复并写回归测试。”
- “学会 = 能判断一条政策说法是否仍有效，并说出依据和不确定处。”

目标太宽时，先收窄到一个本次能验收的任务；不要用“了解 X”当目标。

目标定下后，同时写下本次验收任务和通过标准，优先外部题源；纠错用没见过的错误，迁移至少改一个结构变量。

## 0.1 三种入口

| 入口 | 判定 | 动作 |
|---|---|---|
| 教学 | 完全不会 | 建模 → 示例 → 你做 → 反馈 |
| 任务优先 | 会一点 / 换场景就错 | 先给一个任务；失败再教，不从头讲 |
| 只评估 | 只是想检验 | 只跑探针和闸门任务，输出证据；不建模、不给例 |

模式由“现在卡在哪”决定；不确定时先问一个能区分的问题，不默认从头教。

## 1. 探测

目的不是考试，是找最小卡点。默认 1–3 个问题或一个小任务。探测前先有一个轻量目标结构（5–9 个节点，见 `knowledge-reshaping.md`）；没有结构就不知道在探哪个节点。

规则：

- 一次只问一个；用户答完再决定下一个。
- 先问能暴露模型的题，不问名词定义。
- 允许用户说“不知道”；不知道本身就是证据。
- 不在探测前开始长篇讲解。
- 目标很宽或用户要系统计划时，才用 4–6 题诊断地图；仍然一次一题。

按类型的最小探针：

| 类型 | 探针 | 看什么 |
|---|---|---|
| 模型类 | “如果 batch size 翻倍，显存和吞吐分别怎么变？为什么？” | 是否有因果模型，是否只会背结论 |
| Harness 类 | “这个报错你会先看哪里？给我一条命令或一个文件。” | 是否会定位，是否只会改症状 |
| 世界知识类 | “这句话你现在信几分？需要什么来源才能确认？” | 是否有来源意识和校准 |
| 通用技能·程序性 | “给我一个你做过的标准任务；再做一遍并说出关键判断。” | 能否独立完成、是否依赖提示 |
| 通用技能·概念/判断 | “给你一个案例，你的判断是什么？什么条件下会改判？” | 是否有论证和边界，不是背结论 |

探测结束的标志：能说出一个具体卡点，或确认没有明显缺口。说不出来就再问一个，但不要连续问超过 3 个而不给任何教学内容。只评估模式除外：用验收任务代替提问，每个闸门 1 个任务，最多 6 个；开场说明本次只评估。

## 2. 建模

给最小的正确心智模型，不是完整教材。

顺序：

1. **形状**：一句话说清它解决什么问题、由哪几个部分组成。
2. **关键决策**：哪两三个选择决定结果。
3. **细节**：只在用户要做题或出错时补。

约束：

- 一次只引入一个新概念；新术语首次出现时用一句话解释。
- 先给因果，再给名词。
- 不超过 3 层缩进或 3 个并列分支；超了就拆成下一步。
- 讲完停一下，用一个问题确认模型是否建立。
- 仅“教学”入口：首次接触概念给完整模型 + worked example；用户尝试后才切到最小提示。不要把“不替用户思考”理解成首次教学也只用追问。任务优先和只评估入口不给模型和示例。

## 3. 示例

一个完整 worked example，展示判断过程，不只展示结果。

示例必须包含：

- 输入和约束。
- 关键判断点：为什么选这个，不选那个。
- 一个常见错误及为什么错。
- 可验证的输出。

不要用“显然”“很简单”跳过步骤；用户卡住的地方往往就在这些步骤。

## 4. 你做

必须让用户产生可观察输出：

- 复述模型（用自己的话）。
- 预测一个结果，再验证。
- 改一行代码或配置，观察变化。
- 做一个小题，写出理由。
- 指出一个反例或边界。
- 给一段材料，让用户判断来源可信度。

不要用“你理解了吗？”作为检查；用户说“懂了”不算证据。

## 5. 反馈

先分类，再回应：

| 错误类型 | 表现 | 回应 |
|---|---|---|
| 事实缺口 | 不知道关键定义/数据 | 补最小事实，立刻回到应用题 |
| 模型错误 | 因果反了、混淆相关与因果 | 问“你刚才假设了什么”，用对比案例重建 |
| 步骤错误 | 知道原理但顺序/操作错 | 拆步骤，让用户重走关键一步 |
| 迁移失败 | 原题会，换场景不会 | 指出变化点，给一个半提示的新题 |
| 读题错误 | 答了另一个问题 | 复述问题，确认约束，不重复讲知识 |
| 无法分类 | 证据不足 | 问一个能区分两类错误的问题，不硬归类 |

反馈规则：

- 引用用户原话或具体题号，不做人格判断。
- 对的部分要具体说对在哪；错的部分要说错在哪一步。
- 一次只改一个主要错误；不要把所有问题一起倒出来。
- 用户答对但理由错，按“未过关”处理；答错但推理对，肯定推理再修事实。

## 6. 重塑

按反馈换讲法，不是重复同一句。先判断缺节点、错边、混淆还是缺边界（见 `knowledge-reshaping.md`）：

| 卡点 | 重塑动作 |
|---|---|
| 台阶太大 | 降一步，先做子问题 |
| 太抽象 | 换具体例子、数字、图 |
| 混淆两个概念 | 给对比案例，列相同点和不同点 |
| 缺前置 | 补一个最小前置，再回到原题 |
| 太简单/已经会 | 加边界、反例、对抗性问题 |
| 过载/挫败 | 停止提问，给完整样例，再做一个小检查 |
| 目标漂移 | 复述目标，问是否换方向 |

重塑后必须再探测，不能讲完就默认会了。

## 7. 再探测

换一个角度验证同一目标：

- 换场景、换参数、换约束。
- 让用户从错误答案里找错。
- 让用户解释“为什么不是另一个选项”。
- 让用户设计一个能区分会/不会的小测试。

不要原题重考；原题重考测的是记忆，不是掌握。

## 8. 节奏与停止

- 一次只问一个问题；用户回答后再决定下一步。
- 连续两轮没有具体例子或可观察输出 → 停止提问，给 worked example。
- 用户说“直接说”“别问了” → 立即给完整解释，然后只做一个检查。
- 用户明显疲劳或时间不够 → 收束，给学习地图和复习点，不硬撑。
- 达到“本次过关”（见 `mastery-gates.md`）→ 收束；不要在教学/评估会话收束时宣布“已掌握”；掌握复测（7 天后）可以判。
- 只验证了部分闸门 → 报“本次未判定（轻量或只评估）”，写明哪些闸门 `○ 未测`；不要用轻量路径的单个检查报过关。

## 9. 与长期轨道的关系

单次会话默认不建课程。目标跨周/跨月时，先从 `curriculum-track.md` 的课程地图取一个能力点，再跑本循环。

- 阶段 0–1：跑本循环。
- 阶段 2–4：跑评审循环，不从头讲；见 `curriculum-track.md`。评审判定 = 产物达到教学前写下的验收标准 + 用户能解释关键决策；六道闸门只在回落教学时用。
- 有课程地图：会话结束写回证据、缺口、下一项目、绝对复习日期、节点状态和关键边。
- 没有课程地图：只保留内部记录，不假装已保存。

## 10. 一轮的最小记录

内部记录，不输出整表；建了长期轨道时，把“证据/缺口/下一步/复习日期”写回课程地图：

```text
本轮目标：
用户输出：
证据：
错误类型：
下一步：
学习者模型变化：
是否写回课程地图：
```

输出给用户时只保留“下一步”和一句模型变化。
