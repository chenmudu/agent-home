# 主题类型与主工作流

先看可观测信号，再看主题名称。**类型决定证据形态和主工作流，不决定教学法。** 教学法由学习者水平和当前卡点决定（见 `teaching-strategies.md` 的通用策略）。

| 类型 | 可观测信号 | 典型词 | 主工作流 |
|---|---|---|---|
| **模型类** | 涉及训练、推理、指标、数据、算力、参数、实验对照 | benchmark、loss、SFT、RLHF、量化、显存、消融、吞吐、延迟 | 预测 → 实测/查表 → 归因 |
| **Agent Harness 类** | 涉及代码、命令、报错、工具调用、上下文、状态、重试、文件位置 | 仓库、函数、调用链、`file:line`、trace、hook、MCP、权限 | 样例渐隐 + 真实代码走查 |
| **世界知识类** | 涉及外部事实、时间、来源、政策、版本、价格、人物、新闻 | 最新、发布、政策、价格、排名、谁、什么时候 | 检索 → 来源批判 → 校准 |
| **通用技能** | 可重复的动作、表演、身体/语言技能，或需要论证与判断的概念 | 通用技能·程序性：钢琴、演讲、外语、运动、手工；通用技能·概念/判断：统计、合同法、医学概念 | 通用技能·程序性：示范 → 分解 → 练习 → 即时反馈 → 变式 → 整合；通用技能·概念/判断：worked example → 对比案例 → 主动回忆 → 论证练习 |

## 判定顺序

1. 用户要完成的动作是什么：算/实验、修/读代码、查/判断外部事实、练一个技能。
2. 证据在哪里：实验数据、仓库与运行时、公开来源、可观察的表演/产物。
3. 选一个主类型；其他类型只作为前置或补充，不并列混用。

例：

- “手算 attention 的参数量和显存” → 模型类。
- “Claude Code 的工具审批为什么卡住” → Agent Harness 类。
- “这个模型今天发布了吗、价格多少” → 世界知识类。
- “教我弹钢琴” → 通用技能·程序性；“教我统计假设检验 / 读合同法” → 通用技能·概念/判断。
- “读 transformer 论文并复现实验” → 模型类为主，论文阅读和代码是手段。

## 冲突与混合

- **目标混合**：以用户最终要交付的产物定主类型。要跑实验就是模型类；要修仓库就是 Harness 类；要判断外部事实就是世界知识类；要练可观察技能或判断力就是通用技能。
- **前置混合**：学 Harness 需要模型知识时，模型知识标为前置，不切换整门课的主工作流。
- **教学法切换**：同一主题内可以根据卡点换教学法（如从 worked example 切到对比案例），一次只用一个主方法，切换时说明理由。
- **用户纠正**：用户说“不是这个方向”时立即切换，不争辩；先复述新目标，再重新探测。
- **判不出来**：只问一句“你更想会做哪件事：跑实验、改代码、判断一个外部说法，还是练一个具体技能？”不要靠猜。

## 判定后的动作

向用户明示一次，并允许纠正：

> 我按「模型类」教：先用预测和实测建立因果，再读指标。如果你其实想解决的是代码报错，告诉我，我切到 Harness 类。

水平不决定主题类型，只决定入口模式（教学 / 任务优先 / 只评估）；分类只服务于选证据形态和主工作流。

## 与教学法的对应

- 模型类 → `teaching-strategies.md` 的「模型类」
- Harness 类 → `teaching-strategies.md` 的「Agent Harness 类」
- 世界知识类 → `teaching-strategies.md` 的「世界知识类」
- 通用技能 → `teaching-strategies.md` 的「通用技能·程序性」或「通用技能·概念/判断」

判定不是一次性的；目标变化时重新判定，并说明为什么切换。

## 高风险/身体技能

手术、飞行、临床、极限运动等必须由持证人类教练在场监督；本技能只做知识、决策和复盘，不替代实操。
