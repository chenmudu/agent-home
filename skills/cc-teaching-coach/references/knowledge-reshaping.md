# 知识重塑：先有目标结构，再谈因材施教

学习者模型回答“他现在会什么”；知识结构回答“要学会的东西由什么组成、先学什么、哪里容易混”。缺后者，“重塑”就只是换一种说法。

## 1. 建目标结构（本次 5–9 个节点）

只覆盖本次目标，不画整门学科。

| 节点 | 类型 | 一句话 | 前置 | 对比/边界 |
|---|---|---|---|---|
| | 概念 / 步骤 / 事实 / 判断 / 工具 | | | |

边比节点重要：

- **前置**：不会 A 就学不了 B。
- **组成**：B 由 A1、A2 构成。
- **对比**：A 与 A' 容易混，差别在哪个变量。
- **因果**：X 导致 Y，成立条件是什么。
- **失败**：在 Z 条件下不成立，或代价过高。

节点超过 9 个就拆成两次；一次只教一个可验收的切片。

## 2. 叠加学习者状态

每个节点标一个状态，并附证据：

| 状态 | 含义 | 证据 |
|---|---|---|
| 稳 | 能独立解释、应用 | 具体题号/输出 |
| 半懂 | 能复述，换场景就错 | 哪一步卡住 |
| 缺 | 没有这个节点 | 没答出/没用到 |
| 误解 | 有错误信念 | 原话 + 正确口径 |
| 未验证 | 没测过 | 不写成“已会” |

没有证据的节点一律标“未验证”。

## 3. 找最小缺口

优先级从高到低：

1. **缺前置**：不补就讲不通。
2. **误解**：越练越错，必须先拆。
3. **混淆**：两个节点粘在一起，需要对比。
4. **缺边界**：会做题，但不知道何时不适用。
5. **缺事实**：补一句就够，不要展开成整课。

一次只动一个节点或一条边。不要同时修整张图。

## 4. 重塑动作

| 问题 | 动作 | 例 |
|---|---|---|
| 缺节点 | 补最小概念，立刻回到应用题 | 缺“状态”概念 → 先画一次状态转移 |
| 错边 | 用对比/反例拆掉错误因果 | “模型更大 → 一定更好” → 同参数不同数据反例 |
| 节点混淆 | 并列对比，列出同异和判别问题 | 召回 vs 重排：输入、目标、失败模式 |
| 步骤错序 | 用状态机/流程图重排 | 先重试单步，还是重跑整链 |
| 缺边界 | 给失败案例和代价 | 缓存失效、超时、权限拒绝 |
| 孤立事实 | 接到已有节点上 | 新 API 接到“入口 → 状态 → 输出”链 |
| 类比误导 | 换类比，并明确不同点 | “上下文像内存”要补“没有指针、会截断” |

重塑后必须验证，不能讲完就默认会了。

## 5. 验证

- 让用户自己画或说结构：节点、边、边界。
- 给一个新场景，看是否用对边，而不是背对节点。
- 问“如果去掉 X，会怎样？”检查依赖关系。
- 问“什么情况下这个方法不成立？”检查边界。
- 更新地图；没测过的保持“未验证”。

## 6. 两个例子

**Harness 类：报错定位**

节点：入口、状态、工具调用、重试、日志。
学习者把“重试”连成“重新执行整个任务”——这是错边。
重塑：对比“重试单步”与“重跑整链”的状态变化，画一次状态图，再给一个新报错让用户判断该重试哪一步。

**模型类：benchmark 判断**

节点：数据、指标、对照、算力、污染。
学习者把“分数高”直接连到“能力强”——缺边。
重塑：加“评测口径/数据污染”节点，给同分不同数据的反例，再让用户读一张新表找混杂因素。

## 7. 反模式

- 一上来画 30 个节点，用户看不到重点。
- 只讲节点，不讲边；用户会背名词但不会判断。
- 把用户复述的词当成“节点已稳”。
- 地图建完不更新，下次又从零开始。
- 一次改整张图，无法归因哪一步有效。
- 用“知识图谱”包装一堆未验证的猜测；没有证据的边标“假设”。
