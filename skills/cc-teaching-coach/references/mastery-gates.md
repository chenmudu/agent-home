# 掌握闸门：本次过关、未判定与已掌握

## 1. 判定矩阵与会话/掌握判定

| 场景 | 允许的判定 |
|---|---|
| 教学 / 只评估会话收束 | 本次过关 / 未过关 / 本次未判定 |
| 评审会话（阶段 2–4） | 评审通过 / 评审未通过 |
| 掌握复测（7 天后） | 已掌握 / 未掌握 |

掌握有两个等级：本次过关、已掌握。“本次未判定”是证据不足状态，“未掌握”是否定判定，只用于掌握复测；两者都不是等级。

- **本次过关（provisional）**：这个能力点在本次会话里达到了可独立使用的标准。它不是“已掌握”，不能对外说“学会了”。
- **已掌握（verified）**：跨场景、跨时间仍能独立做对，并有证据。只有这个判定可以用“掌握”。
- **本次未判定（轻量或只评估）**：只验证了部分闸门，证据不足以下结论。写明哪个闸门有证据、哪些 `○ 未测`。
- **未掌握（仅掌握复测）**：六项中任一不是“过”。写明哪一项、什么证据、下一步练什么。

掌握学习要求每个目标都到标准，不是“六项过三项”。本次过关只覆盖三项；已掌握要求六项全过。

| 闸门 | 本次过关 | 已掌握 | 可接受证据 | 不可接受证据 |
|---|---|---|---|---|
| **解释** | 必过 | 必过 | 用自己的话讲清因果、组成、边界 | 背定义、堆术语、复述原文 |
| **应用** | 必过 | 必过 | 在新任务里独立做对 | 照抄示例、只改数字 |
| **纠错** | 必过 | 必过 | 能指出并修正一个常见错误 | 只会说“错了”，说不出为什么 |
| **迁移** | 可留到复习 | 必过 | 至少改一个结构变量（场景/约束/数据）仍能判断 | 原题重考、只换数字或措辞 |
| **保持** | 可留到 7 天复测 | 必过 | 至少隔 7 天仍能回忆和应用 | 刚讲完立刻复述 |
| **校准** | 可留到复习 | 必过 | 先写置信度/预测 → 做 → 对照结果，至少 2 次记录 | 只说“我知道自己哪里不确定”，或全部说“懂” |

规则：

- 本次过关 = 解释、应用、纠错三项都过；不要求迁移和保持。
- 已掌握 = 六项全过；其中保持必须在至少 7 天后复测，迁移必须用新场景。只在掌握复测时判，不在会话收束时判。
- 任何一项没过，不要用其他项的通过抵消；直接指出哪一项、什么证据。
- 单次教学/评估会话收束不能判“已掌握”，只能判“本次过关”“未过关”或“本次未判定”；掌握复测可以判“已掌握/未掌握”；评审会话判“评审通过/未通过”。

## 2. 状态词汇

状态优先写文字：`过 / 部分 / 未过 / 未测`；表格里可简写为 `✅ / ◐ / ✗ / ○`。不用分数、百分比、进度条：

| 状态 | 含义 |
|---|---|
| `✅ 过` | 独立完成，并能说出理由 |
| `◐ 部分` | 需要提示，或答案对但理由错，或表现不稳定 |
| `✗ 未过` | 错误，或没有可用的证据 |
| `○ 未测` | 本次没测；不要当成通过 |

示例：

```text
解释 ✅  应用 ✅  纠错 ✅  迁移 ○  保持 ○  校准 ◐
→ 本次过关；未验证掌握。7 天后复测迁移、保持、校准。
```

## 3. 会话闸门与阶段闸门

- **会话闸门**：教学/只评估会话里，本次一个能力点是否过关，用上面的六项；评审会话不用六项。
- **阶段闸门**：能否进入下一阶段，按阶段递增；越高阶段越需要跨任务、跨时间、真实项目、外部反馈、能教别人；见 `curriculum-track.md`。
- 一次会话的“本次过关”或“评审通过”只决定当前能力点/项目，不能当阶段晋升证据。
- 阶段 2–4 用评审循环，不重复新手教学循环；见 `curriculum-track.md`。
- 评审会话的判定不是六项，而是“产物达到教学前写下的验收标准 + 用户能解释关键决策”；六项只在回落到教学时用于那个能力点。

## 4. 证据规则

- 每条判定必须能回指到：题号、用户原话、代码/命令输出、作品链接、评审原文。
- 用户说“懂了”“会了”不是证据；让用户做一步、讲一遍或交一个产物。
- 教学前先写下验收任务和通过标准；优先用外部题源（真实报错、benchmark、用户项目、过往考题），少用自己现编的同构题。
- 纠错题用用户没见过的错误，或让用户在自己的产物里找错；迁移题至少改一个结构变量。
- 自评只能作为线索，不能单独判定“已掌握”，也不能单独通过阶段闸门。
- 外部专家认可、领域影响、方法被采用，必须有可检查的产物；无法核实的标“用户报告，未验证”，且不得用于阶段晋升。
- 证据分级（高到低）：公开可访问（URL/PR/DOI）> 可复现（命令/数据/产物）> 截图/转述（标未验证）> 口述（不作为晋升证据）。3→4 的“外部认可/领域影响/方法被采用”只认前两级；人类专家评审本身可记为第三级，只满足“专家评审”要求。
- 证据不足时标 `○ 未测`，不要猜。

## 5. 只评估模式

用户说“检验我是不是真的会了”时：

1. 只做探针和验收任务，不建模、不给完整示例。
2. 按六道闸门记录状态和证据。
3. 输出“过 / 部分 / 未过 / 未测”和下一步，不宣布“掌握”。
4. 六道闸门都有状态（含 `○ 未测`）或用户时间用完就停；不为了凑证据无限加题。
5. 用户要求再教时，才切回教学循环。

## 6. 验收任务

按类型给一个新任务，不用原题：

| 类型 | 验收任务 |
|---|---|
| 模型类 | 给一个没见过的 benchmark/消融表，判断结论是否成立，指出至少一个混杂因素 |
| Harness 类 | 给一个没见过的报错或小仓库，定位 `file:line`，提出最小修复和回归测试 |
| 世界知识类 | 给一条时效性说法，找两个来源交叉验证，标出日期、范围和不确定处 |
| 通用技能·程序性 | 给一个没见过的标准任务，在时间/约束下独立完成，并解释关键判断 |
| 通用技能·概念/判断 | 给一个没见过的案例或论证，判断结论是否成立，写出理由、反例和不确定处 |

验收任务必须：

- 有新场景或新约束。
- 有可观察输出（答案、代码、命令、作品、判断）。
- 有明确通过标准。
- 允许用户说“不确定”，但要说明不确定在哪。

## 7. 复习与保持

- 24 小时内：一次主动回忆（不看笔记，先写再对照）。
- 7 天后：一个换场景的小任务，用来判“保持”和“迁移”。
- 30 天后：混合旧题，检查辨别。
- 90 天后：真实项目/教学，检查迁移。
- 复习结果：长期轨道写回课程地图的节点状态和关键边；单次会话写进学习地图；没测过标 `○ 未测`。
- 把复习日期写成绝对日期交给用户，不假设系统会自动提醒。

## 8. 常见误判

- **把流畅当掌握**：用户能复述你的话，不等于有自己的模型。
- **把一次正确当稳定**：加一个参数或换一个场景再确认。
- **把沉默当不会**：可能是问题太大；降台阶再试。
- **把自信当掌握**：自信但错是校准问题，先预测再验证。
- **把本次过关当已掌握**：7 天后复测之前，不说“掌握”。
- **用其他项掩盖缺口**：一项没过就是没过，不做跨项平均。
