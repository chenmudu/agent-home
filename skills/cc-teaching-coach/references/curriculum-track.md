# 长期轨道：从 0 到专家

单次会话解决一个卡点；长期轨道解决“先学什么、练什么、谁来判、怎么保持”。目标不是把课表排满，而是让每一阶段都有可验证的专家行为。

## 1. 什么时候建轨道

建：

- 用户明确说“从零到专家”“系统学”“几个月/一年”。
- 目标跨周/跨月，或需要真实项目/作品。
- 单次会话已经覆盖不了前置链。

不建：

- 一次性问答、只补一个概念、只想解决当前报错。
- 用户没给时间/目标；先做单次教练。

默认：先单次教练；用户要长期目标时再建轨道，不主动塞整张课表。

## 2. 先写专家画像

不要写“学会 X”，写专家能做什么：

```text
专家画像：
- 能解决：<未见问题/复杂问题>
- 能产出：<作品/决策/方案>
- 能判断：<取舍/边界/风险>
- 被谁认可：<专家/用户/社区/市场>
```

画像来源：

- 先问用户有没有目标专家或目标作品；有就以它为样本。
- 没有就检索 3–5 个公开样本：该领域专家的作品、评审意见、招聘标准、公开项目；记来源和日期。
- 没有样本就标“假设，待验证”，不要当成事实。
- 画像不是“知识清单”；它描述可观察的行为和产物。

## 3. 五个阶段（0–4）

阶段表是画像，晋升以 §4 的闸门表为准。

| 阶段 | 目标 | 主方法 | 过关证据 |
|---|---|---|---|
| 0 入门 | 正确模型 + 基本词汇 | 直接教学、工作样例、即时反馈 | 能解释核心模型；能照做标准例；能指出并修正一个常见错误；无主要误解 |
| 1 合格 | 独立完成标准任务 | 渐隐、变式、交错、掌握学习 | 至少 3 个标准任务无提示完成（建议 3–5 个）；能说理由；7 天后仍能做 |
| 2 熟练 | 处理真实项目/失败 | 项目阶梯、故障诊断、刻意练习、评审循环 | 至少 2 个真实项目（建议 2–3 个）；复盘；每个项目至少一次人类专家评审 |
| 3 专家 | 解决未见问题/做取舍 | 前沿问题、原创产出、专家学徒、教学 | 原创作品/方案；每个项目至少一次人类专家评审；能教别人 |
| 4 巨牛 | 定义问题/创造方法 | 开放问题、跨域整合、带人 | 领域影响、方法被采用、培养出至少 1 名能独立工作的他人（理想是专家） |

“巨牛”不是课程毕业证，是领域认可；教练不能认证，只能维护证据清单。

## 4. 阶段闸门

闸门按阶段递增，不要用同一套标准卡所有人：

| 晋升 | 必要证据 | 不要求 |
|---|---|---|
| 0 → 1 | 解释、应用、纠错过关；7 天后不看笔记仍能解释和应用（同类型任务） | 真实项目、外部专家、迁移到新领域 |
| 1 → 2 | 至少 3 个标准任务无提示（建议 3–5 个）；至少 2 种任务类型；7 天保持；同伴评审或可检查产物（自查仅辅助） | 真实项目 |
| 2 → 3 | 至少 2 个真实项目（建议 2–3 个）；每个项目至少一次人类专家评审（无专家 → 标未验证，不晋升）；失败复盘；能教别人 | 领域影响 |
| 3 → 4 | 原创作品/方案；每个项目至少一次人类专家评审（无专家 → 标未验证，不晋升）；外部认可；方法被采用；培养出至少 1 名能独立工作的他人（理想是专家） | 课程完成 |

数字是经验默认，不是硬阈值；按领域和用户时间调整，但不得低于“至少”。2→3 和 3→4 没有人类专家评审时，阶段证据标“未验证”，不得晋升。

阶段 × 项目阶梯：

| 阶段 | 项目级别 |
|---|---|
| 0 入门 | 1–2 |
| 1 合格 | 3 |
| 2 熟练 | 4–5 |
| 3 专家 | 6 |
| 4 巨牛 | 6 + 原创产出 |

单次会话的“本次过关”或“评审通过”只决定当前能力点/项目，不决定阶段晋升；见 `mastery-gates.md`。

阶段没过时：指出哪道闸门没过 → 一个刻意练习任务 → 约定复测日期；不要直接重学整门课。

前置链超过 2–3 层时，收窄本次目标，先补最近的前置，不一次追到最底层。

## 5. 教学循环 vs 评审循环

阶段 0–1 用教学循环：

```text
探测 → 建模 → 示例 → 你做 → 反馈 → 重塑
```

阶段 2–4 用评审循环：

```text
用户带产物/尝试
  → 对照专家画像和阶段标准
  → 只找最高杠杆的一个缺口
  → 给针对性练习/修改任务
  → 用户改，再评审
```

规则：

- 阶段 2 以后，教练是评审者，不是讲师；不要从零讲一遍。
- 一次只改一个最高杠杆问题；不要列十条泛泛建议。
- 杠杆顺序：产物是否成立/能否交付 > 是否可复现/可验证 > 约束下是否最优 > 表达/效率。只改当前最高的一层，不改下一层。
- 停止：产物达到教学前写下的验收标准，或同一产物改了两轮仍无新证据，就停；不要无限打磨。
- 评审判定 = 产物达到验收标准 + 用户能解释关键决策；不是六道闸门。
- 评审者分层：教练评审只查证据、结构、可复现性；取舍、新颖性、领域标准交给人类专家（见 §8）。
- 发现缺前置，才回落到教学循环补那个节点，补完回到产物。
- 评审必须看产物或可观察输出，不看“我觉得”。
- 每次评审留下：证据、缺口、下一版要改什么。

## 6. 项目阶梯

| 级别 | 项目类型 | 模糊度 | 新能力 |
|---|---|---|---|
| 1 | 复现工作样例 | 低 | 看懂步骤和判断 |
| 2 | 改一个变量/参数 | 低 | 预测与归因 |
| 3 | 标准任务，无提示 | 中 | 独立执行 |
| 4 | 信息缺失/故障排查 | 中高 | 诊断与取舍 |
| 5 | 真实项目，有后果 | 高 | 交付与沟通 |
| 6 | 开放问题，无已知答案 | 极高 | 定义问题/原创 |

规则：

- 每级至少 2 个不同案例（建议 2–3 个），避免只记住一个。
- 升级看证据，不看时间。
- 卡住时降一级，不硬跳。
- 项目必须有验收标准和复盘。
- 项目来源程序：先问用户当前工作、开源 issue、社区需求里有没有真实项目；有就选一个，开始前写验收标准和后果。选择标准：有真实后果、能拿到反馈、规模可在 1–3 周内交付；太大就切小。没有真实项目时，用带人类专家评审的模拟项目，并标“模拟，局限是……”。不要只用虚构练习。

## 7. 刻意练习

不是重复已会的，而是打弱点：

1. 选一个具体弱点，不是“我不熟 X”。
2. 设计一个可重复的小任务。
3. 做，立刻得到反馈。
4. 修正，再做一次。
5. 逐渐加难度/换场景。

默认剂量：

- 默认每周 3–5 次（经验值，不是硬阈值），每次只练一个弱点。
- 任务在能力边缘：有挑战但能完成。
- 反馈具体到决策/步骤，不是“不错”。
- 记录错误类型和修正。
- 低于这个频率时，明确标“维持模式”，不承诺进阶速度。

## 8. 专家反馈与证据审计

| 来源 | 作用 | 频率 |
|---|---|---|
| 自查 | 发现明显错误、记录假设 | 每次 |
| 同伴 | 横向对比、复现问题 | 每周 |
| 专家 | 判断品味、边界、取舍 | 每 1–2 周 |
| 真实用户 | 验证价值/可用性 | 每个项目 |

问专家具体问题：

- “这个决策在什么条件下会失败？”
- “如果换约束，你会怎么改？”
- “我漏了哪个信号？”
- “这段工作离专家差在哪一步？”

评审者分层：

- **教练评审**：对照教学前写下的验收标准，检查证据、结构、可复现性、是否回答了问题；不能判“专家级品味/新颖性/领域标准”。
- **人类专家评审**：判断取舍、新颖性、领域标准；阶段 2→3 和 3→4 每个项目至少一次。
- 教练负责准备评审包：产物、验收标准、证据、3 个具体问题；拿到专家反馈后转成下一版任务，并把自己的评审标成“教练评审，非专家认证”。

没有人类专家时：

- 可以先用同伴评审、公开评审、真实用户反馈补证据，但 2→3 和 3→4 的阶段证据标“未验证”，不得晋升。
- 明确写“缺少专家评审，结论有局限”，不要包装成专家认可。

证据审计：

- 要求作品链接、PR、评审原文、发表记录、用户反馈等可检查产物。
- 用户口述的“专家认可了”只能记为“用户报告，未验证”，不得用于阶段晋升。
- 证据分级（高到低）：公开可访问（URL/PR/DOI）> 可复现（命令/数据/产物）> 截图/转述（标未验证）> 口述（不作为晋升证据）。3→4 的“外部认可/领域影响/方法被采用”只认前两级；人类专家评审本身可记为第三级，只满足“专家评审”要求。
- 阶段 3–4 的“外部认可/领域影响”必须由教练之外的证据支持；教练不能认证巨牛。

## 9. 复习与保持

- 24 小时：主动回忆核心模型。
- 7 天：换场景做一个小任务，判保持和迁移。
- 30 天：混合旧题，检查辨别。
- 90 天：真实项目/教学，检查迁移。
- 每次 1–3 个点，不搞大规模重读。
- 把复习日期写成绝对日期交给用户；不要假设系统会自动提醒。
- 复习结果写回课程地图；没测过标 `○ 未测`。

## 10. 作品集

每阶段留下：

- 作品/项目链接。
- 决策日志：当时怎么想、备选方案、结果。
- 复盘：错在哪、下次怎么改。
- 专家/用户评语。
- 教学材料：证明你能讲清。

作品集是阶段闸门的证据，不是装饰。

## 11. 状态持久化协议

长期轨道必须落盘，否则跨会话就断。

默认路径：

```text
./.teaching/<slug>/curriculum-map.md
```

`<slug>` 是主题短横线名（如 `llm-inference`），重名加日期。默认在当前目录；创建前提醒用户把 `.teaching/` 加进 `.gitignore`。用户指定路径时从用户。

开始时：

1. 读用户指定的地图；没有指定就看默认路径。
2. 文件存在：读当前阶段、能力点、节点状态和关键边、开放复习项。
3. 文件不存在：只问一次“要不要建课程地图？”用户同意才创建。
4. 没有长期目标：不建文件，只保留会话内记录。

结束时：

1. 把本次证据、缺口、下一项目、节点状态和关键边写回地图。
2. 把复习项写成绝对日期。
3. 在“会话记录”里追加一行，不重写整张地图。
4. 地图太长时只保留当前阶段 + 下一阶段。

不假装系统会提醒；把日期和任务交给用户。

## 12. 和单次教练怎么接

1. 开始前读课程地图，确定当前阶段和一个能力点。
2. 只取一个能力点：阶段 0–1 跑 `adaptive-loop.md`；阶段 2–4 跑评审循环。
3. 会话结束更新：证据、缺口、下一项目、复习项、节点状态和关键边。
4. 每 2–4 周做一次阶段复盘；不每天改地图。
5. 地图太长时只保留当前阶段 + 下一阶段。

## 13. 时间尺度与外部依赖

- 0 → 合格：可以按周/月规划。
- 合格 → 熟练：通常按月/年，取决于真实项目量。
- 熟练 → 专家：通常以年计，必须有真实项目、真实用户、人类专家反馈。
- 专家 → 巨牛：没有课程时间表；靠开放问题、原创产出、领域认可和带人。
- 教练能提供结构、练习、反馈和证据清单；不能替代真实后果、人类专家、社区和时间。

## 14. 反模式

- 收藏课程代替练习。
- 只做简单题，回避弱点。
- 没有真实项目/后果。
- 没有专家反馈，自己觉得自己行。
- 没有复习调度，学完就忘。
- 用活动量（看完几门课）当进度。
- 地图过细，变成不能调整的课表。
- 自评通过阶段闸门。
- 把教练评审当专家认证。
- 把“用户报告”当外部认可。
- 阶段 2 以后还在从头讲课，不做产物评审。
- 过早专业化，基础缺口没补。
