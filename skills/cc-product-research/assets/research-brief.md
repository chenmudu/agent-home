# 调研简报（开工前写，只问一次）

> 整场调研只会停下来提问一次。只有下面三种情况需要问：① 决策句推不出；② 会花 LLM 额度或往对象侧写盘（写你自己的报告不算）；③ 产出位置/形态有歧义。其余情况写完六行简报直接开工。

## 1. 决策句与读者模式

这份报告要回答谁的什么问题？

```
我们准备 <做什么决定>，需要知道 <对象的什么>。
```

从决策句推断读者模式，不额外提问；默认 `evaluator`。

| 模式 | 判据 | 第一屏重点 | 正文展开 |
|---|---|---|---|
| `evaluator` | 要不要用 / 选哪个 | 结论、代价、适合谁 | 五幕 + 主线上 3 个关键功能档案；另 3 个进证据附录（总 ≥6） |
| `operator` | 怎么装 / 怎么跑 / 怎么排障 | 最短路径、失败路径、回滚 | 第一、二、三幕展开；功能档案 ≥6（可短） |
| `maintainer` | 怎么改 / 怎么接 / 会不会坏 | 机制、边界、维护成本 | 五幕 + 6 个功能档案 + 15 处源码引用 + 6 个文件 |

读者模式只改变“先讲什么、讲多深”，不降低证据下限。

## 2. 对象

| 项 | 值 |
|---|---|
| 名称 | |
| 版本 | |
| 证据来源 | 上游 tag / 本机安装 / 线上环境（含 URL） |
| SSOT 声明 | 以哪个为准（安装副本与上游不一致时怎么处理） |

## 3. 访问面

| 项 | 值 |
|---|---|
| 形态 | Web 页面 / 桌面 App / CLI / API / 混合 / 自家生态 / 源码 + 文档 |
| 驱动 | browser-use / computer-use / 终端 / curl / 源码读取 |
| 探针 | 通过 / 失败 → 改用（手工截图 / 源码 / 文档） |
| 取证通道 | S 源码 / R 运行时 / D 文档（可多选） |
| 编排 | 单主 agent / 主控 + N worker（S×? / R×? / D×?）；并行或串行 |
| 备注 | 登录、权限、平台差异 |

> 一个产品可能有多个访问面：先选用户主路径那个，其余作补充证据（见 `references/access-surfaces.md`）。没有可运行实例时，源码 + 文档是合法访问面，不写“降级”；只有源码时第一屏写“未实机”。

|---|---|---|

## 5. 操作许可

| 级别 | 本次是否允许 |
|---|---|
| L0 浏览 | |

## 6. 起点与停止

- 起点级别：A / B / C / D / E
- 打算走到哪一级、为什么（到“能判断”即可）
- 什么情况下不往下走（成本、无权限、证据已够）

## 7. 产出

| 项 | 值（默认） |
|---|---|
| 契约版本 | `contractVersion: 3` + `reader` |
| 第一屏 | 决策简报：7 行（一句话 / 给谁用 / 怎么用 / 代价 / 本次没做到 / 该不该试 / 下一步）+ 3 个 KPI |
| 正文骨架 | 五幕：a1 进入 → a2 安装后 → a3 核心链路（输入 / 处理 / 输出）→ a4 承载者 → a5 横切 |
| 主线预算 | 五幕 + 6 个功能档案；每块“产品意图 → 代码确认 → 判定” |
| 证据深度 | 源码引用 ≥15 处、覆盖 ≥6 个文件；宣称/可见/实现每行有代码引用或“无实现”；至少一次口径对照 |
| 证据附录 | `appendix-evidence` / `appendix-selfproof` / `appendix-refs` |
| 读者验收 | 交付前独立 reader 三段验收，`[读者验收]` 写进 `appendix-selfproof` |
| 语言纪律 | 一句话 ≤120 字；术语首次解释；KPI 标签自解释；数字带口径 |
| 形态 | **单文件自包含 HTML**（截图以 data URI 内嵌，不产出 shots/） |
| 位置 | `<workspace>/.research/<slug>/<YYYY-MM-DD>-v<N>.html`（用户指定则从指定） |
| 版本 | `<N>` = 该对象已有报告数 + 1（读 `.research/<slug>/index.json`）；**永不覆盖旧报告** |
| 既往调研 | 首次 / 第 N 次（有则列出上一版日期与结论，本次必须写「本版变化」） |
| 语言 | 中文 |
| 视觉 | 结构用 skill 基线；皮肤取自被调研对象的 UI（背景 / 面板 / 主色 / 字体气质） |
| 机器可读 | `<script id="report-meta">` + `index.json`（含 `contractVersion` / `reader`） |

## 示例 A（有可运行实例，evaluator）

```
1. 决策句：我们要在两个同类工具里选一个，需要知道谁的主链路更短、代价更低。
   读者模式：evaluator。
2. 对象：两个工具，版本与本机安装一致，SSOT = 上游 tag。
3. 访问面：Web 页面 / browser-use / 探针通过（能列出页面并打开目标 URL）。
   取证通道：R + S；编排：主控 + 3 worker（R×2 / S×1，两个对象各自串行）。
4. 证据：可运行实例、源码、文档、issue 均有。
5. 许可：L0 + L1；L2/L3 全面禁止。
6. 起点 A，走到 C（要选型）；停止条件：能回答“选哪个、为什么”。
7. 产出：单文件 HTML（截图内嵌），落 .research/<slug>/<日期>-v1.html；五幕 + 6 个功能档案；
   第一屏 7 行 + 3 KPI；index.json 登记；交付后问一次清理。
```

## 示例 B（只有源码，maintainer）

```
1. 决策句：我们准备接入这个仓库的导出层，需要知道它的入口、状态与失败路径。
   读者模式：maintainer。
2. 对象：example/repo，版本 v1.0.0，commit abc1234；SSOT = 上游 tag。
3. 访问面：源码 + 文档（不可运行）/ 驱动：源码读取 / 探针：通过（读到 README 与至少一个入口定义）。
   取证通道：S + D；编排：单主 agent。本次未实机。
4. 证据：源码、README、路由/导出/命令注册点；无运行实例。
5. 许可：L0；L2/L3 禁止。
6. 起点 A（源码 A），走到 B；停止条件：能复述“装完多了什么 → 输入从哪来 → 经过哪些状态 →
   输出是什么、怎么确认 → 谁持有状态”。
7. 产出：五幕 + 6 个功能档案 + 15 处源码引用（覆盖 ≥6 个文件）；
   第一屏“本次没做到”写“未实机”；[读者验收] 写进 appendix-selfproof。
```

## 示例 C（访问面不确定，evaluator）

```
1. 决策句：我们准备试用这个商业产品，需要知道公开能力值不值得进入评估。
   读者模式：evaluator。
2. 对象：某商业产品；只有官网和公开文档，核心功能在登录后。
3. 访问面：先探针：官网可打开；核心功能登录后不可达 → 不派 worker，归 D 文档 + 公开页面；
   取证通道：D + R（仅公开页面）；编排：单主 agent。核心能力标“未验证”。
4. 证据：官网、公开文档、公开页面；无源码、无账号。
5. 许可：L0；公开页面 L1；L2/L3 禁止。
6. 起点 A，停在 A；停止条件：公开能力能判断，登录墙后的能力写“未验证”。
7. 产出：五幕中 R 只覆盖公开路径；第一屏“本次没做到”写“核心功能未实机（登录墙）”；
   [读者验收] 写进 appendix-selfproof。
```
