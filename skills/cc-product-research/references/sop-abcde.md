# SOP：A → B → C → D → E

五级是**加深刻度**，不是五个并列章节。每级都能独立交付，到“能判断”就停。

进入新一级前给用户一页提案：

```
这一级要回答：
我要做的动作：
我需要的证据 / 权限：
产出物：
预计停在哪（什么情况下不再往下走）：
```

提案仍然是一段，不阻塞；每级先交一页简报（7 问），再交完整证据。

---

## A 产品能力（用）

**回答**：它能干什么、谁在什么场景用、好不好用。

**动作**

- 产品侧：**先收集产品事实**——定位（是什么 / 不是什么）→ 目标（解决谁的什么问题）→ 现状（版本、活跃度、维护）→ 问题（用户实际撞到什么）→ 解决方法（核心机制 + 取舍）→ 功能细节（一入口一行）。答不出的标“未确认”，随 A 级推进回填；事实进第 1、2 幕和证据附录，不单独做画像章。
- 产品侧：跑起来 → 画入口地图（导航/标签/菜单/命令）→ **每个入口至少走一遍**（不限条数）→ 另选 3–5 条主路径深入 → 每步截图。
- 产品侧：把空状态、载入、错误、忙时、权限不足都走一遍（产品的诚实度全在这几个状态里）。
- 代码侧（轻）：每个入口追到注册点（哪个插件/模块注册了这个标签/命令），确认归属，避免张冠李戴。

### 源码 A 级（没有可运行实例）

- 入口 = README / CLI help / 路由表 / 导出清单 / 命令注册点。
- 每个入口追到 `路径:行号`；能力写“源码可见，未实机”。
- UX 只能标“未实机”，不能用源码推断界面。
- 截图档案可以为空；第一屏“本次没做到”必须写“未实机”。
- 从错误分支、日志、文档里找失败态；从条件分支和常量找边界。

**产物**：一页简报（7 问）+ 五幕 + 证据附录 + 入口地图 + 五张清单（入口/屏幕/状态/动作/权限）。

**停止条件**：第一屏 7 问能答，五幕主线能复述。

**常见误判**

- 把 README 的功能列表当能力清单（那是宣称，不是能力）。
- 只看首屏，不看空状态与失败态。
- 只截图不动手（用户问“你只看截图？”时，说明这一级没做完）。
- 把相邻产品的入口算到当前产品头上（必须追注册点）。
- **把源码调研当降级**：没有实例不是失败；源码 + 文档是一等模式，写“未实机”即可。
- **用源码推断 UX**：有代码路径不等于用户能看到；UX 只能标“未实机”。

## B 技术机制（懂）

**回答**：怎么做到、边界在哪、会坏在哪、维护成本多大。

**动作**

- 代码侧：只下钻 A 里“用户真的会碰”的链路，不做全仓导览。
- 代码侧：找真相源（谁拥有数据）、派生层（谁只读）、写入路径（谁能改）、边界常量（上限/阈值/超时）。
- 代码侧：找失效模式——硬编码字段名、静默降级、吞异常、缺守卫。
- 产品侧：把每个技术发现翻译成产品后果（翻不出来就降权）。

**产物**：一张数据流图 + 关键数据结构 + 失效模式清单 + 翻译表。

**停止条件**：能回答“它下一步会在哪坏”。

**常见误判**

- 把代码结构当报告提纲（读者拿不到产品判断）。
- 只读 happy path，不看错误分支。
- 相信注释与文档（它们经常滞后于代码）。

## C 对比 / 选型 / 合并（比）

**回答**：几个怎么选、能不能并、并了谁负责什么。

**动作**

- 对每个对象先各做一遍 A + B（不要一边读 A 的代码一边猜 B 的行为）。
- 用**同一把尺子**：同一会话、同一口径、同一测量时刻；口径不同就先声明，不许混算。
- 找真重复（同一个用户问题，两家都给答案）与假重复（看起来一样，解决的是不同问题）。
- 同时开启时会发生什么：抢占同一资源（槽位、配置、数据、预算）就是硬冲突。
- 分工判断：每个对象坐到哪个位子，谁观测、谁干预、谁自动。

**产物**：横向矩阵 + 重复/差异（产品→技术→细节）+ 共存冲突 + 取舍表 + 合并架构。

**停止条件**：能回答“要不要合、合了谁干什么、哪些直接砍”。

**常见误判**

- 把“功能名相同”当重复（要看用户问题是否相同）。
- 用 A 的指标去量 B（口径混算）。
- 只比功能，不比“同时开启时”的行为。
- 把外部候选当成新角色（先定位座位）。

## D 外部方案吸收（借）

**回答**：这个思路/实现值不值得抄，抄哪一部分。

**动作**

- 先写一句“它在我们系统里坐哪个位子”，请用户确认，再评估。**座位错了，后面全错。**
- 判断它是不是替代品：如果它只覆盖一个子步骤，就按子步骤评估，不能整体替换。
- 分开看“立意”与“实现”：立意可以抄，宣称不能抄。
- 分出可搬的四类：结构（原子/状态机）、纪律（守卫/闸门）、度量（口径/降级）、接缝（可替换接口）。
- 只标“增”不标“改”，除非确认要替换现有能力。
- 未验证的社区数字一律标来源与“未复现”。

**产物**：座位判断 + 可搬清单（每条注明是事实还是主张）+ 三条硬约束 + 是否实验的建议。

**停止条件**：能回答“抄哪几条、不抄哪几条、为什么”。

**常见误判**

- 按功能罗列吸收，不定位。
- 因为项目做得烂就否定它的立意。
- 因为立意好就照抄它的实现。

---

## E 失败 / 停更复盘（鉴）

**回答**：它为什么坏、还能不能救、教训是什么。

**动作**

- 时间线：最后提交、最后 release、issue 响应率、PR 积压。
- 死因分层：定位错 / 实现错 / 分发错（版本漂移、包被第三方接管、安装门槛）/ 上游阻塞。
- 对照目标验收：它承诺的每一条，逐条判定达成/未达成，并标出“达成的是次要指标、失败的是承重指标”。
- 可复活性：修一处能不能救，还是要重写。

**产物**：时间线 + 死因分层 + 目标验收表 + 可复活性判断 + 可搬遗产。

**停止条件**：能回答“这套东西还值不值得碰”。

**常见误判**

- 把“没维护”当死因（那只是状态，不是原因）。
- 只用 README 判断它当初想干什么（去读当时的 issue 与 release note）。
- 忽略分发问题（装不上、装错包，也是死因）。

---

## 广度与深度（五级共用）

- **广度不降**：所有可达入口都要走；源码-only 时用 README / 路由 / 导出 / 命令注册点画入口地图。
- **叙事有预算**：正文只留会改变判断的功能和状态；其余进证据附录。
- **深度不降**：引用不是 KPI；每多一处 `路径:行号` 必须改变一个判断。
- **读者模式只改讲法**：`evaluator` / `operator` / `maintainer` 改变先讲什么、讲多深，不降低证据下限。
- **源码是一等模式**：不是降级，不是失败；写“未实机”，不写“本次降级”。
