# 编排：先分诊，再派发

这份文件只回答一件事：一次调研里，主 agent、取证 worker、独立 reader 怎么分工，什么能并行，什么必须串行。

报告结构仍以 `assets/report-kernel.md` 为准；本文件不改变 v3 契约。

## 1. 三个角色

| 角色 | 职责 | 边界 |
|---|---|---|
| **主 agent** | 分诊、拆包、对账、写报告、最终判定 | 唯一写作者；唯一结论责任人；关键结论 100% 复核 |
| **取证 worker** | 只读取证；一包一问；回证据 | 不写报告、不改对象、不发消息、不给最终建议、不互传结论 |
| **独立 reader** | 交付前做三段验收 | 不参与调研；不拿源码、不拿对话记录 |

worker 是主 agent 的取证手段，不是第二个调研作者。reader 是质量闸门，不是第三个调研 agent。

## 2. 两种模式

### A. 单主 agent（简单场景默认）

适用于：

- 单对象、单主访问面；第 3 幕独立功能簇 <3
- 没有多个独立访问面
- 运行时链路只有一条
- 访问面还没探针确认

主 agent 按 SOP 连续做完，不为了“并行”而拆。

### B. 主控 + worker + reader（条件触发）

出现以下任一情况，切换到 B：

- **多对象**：C 级对比、选型、合并，每个对象独立取证
- **多访问面**：同一对象有 ≥2 个互不共享状态的独立访问面（如 Web + CLI）
- **多功能簇**：第 3 幕有 ≥3 个互不依赖的功能或状态节点
- **用户明确要求**并行取证

### 禁止 fan-out

- 第 1 幕「进入」的单条安装/首次运行链
- 同一运行时状态链的多个步骤（登录 → 操作 → 输出）
- 访问面尚未探针确认的“不确定”单元
- 最终结论、跨幕合并、报告写作
- 安全 / 边界结论的最终判定
- 独立 reader 验收

**判断单位是“独立证据单元”，不是幕号，也不是文件数。** 同一状态链上的多个步骤不算独立单元。

## 3. 分诊

每个对象或证据单元先做最小探针，再归入一条通道：

| 通道 | 判定 | 取证方式 | 并行性 | 证据标签 |
|---|---|---|---|---|
| **S 源码** | 有仓库或有源码，可静态读 | `路径:行号`、数据流、注册点 | 可并行 | `[源码]` |
| **R 运行时** | 有可运行实例（GUI / CLI / API） | 浏览器、computer-use、终端、curl | 同一状态链串行 | `[浏览器] [屏幕] [终端] [API]` |
| **D 文档** | 只有 README、官网、release、issue | 宣称清单、待验证问题 | 可并行 | `[文档]` |
| **U 不确定** | 不知道能不能跑、有没有源码 | 主 agent 先做 5–10 分钟探针 | 先不派发 | 探针结果决定 |

### 探针清单

| 通道 | 最小探针 |
|---|---|
| S | 能读到 README，且能找到至少一个入口定义（路由 / 导出 / 命令注册点 / CLI help） |
| R | 浏览器能打开目标 URL 并读到标题；computer-use 能列出窗口；终端 `--help` 有输出；API 拿到状态码 |
| D | 文档可访问，能确认版本 / 日期 / 适用范围 |
| U | 5–10 分钟内能归入 S/R/D；归不进去就标“未验证” |

探针失败就改用可行访问面，或标记未验证；不要让 worker 带着“不确定”去猜。

## 4. 调度

```text
Phase 0  主 agent 分诊（串行）
  每个单元：探针 → S / R / D / U
  U 先探针，再重新路由
        │
        ▼
Phase 1  并行取证（按通道，不按幕号）
  S：S1 ∥ S2 ∥ S3        可并行
  R：R1 → R2 → R3        同一状态链串行
  D：D1 ∥ D2             可并行
        │
        ▼
Phase 2  主 agent 对账（串行）
  源码 ↔ 运行时 ↔ 文档；关键结论 100% 复核
        │
        ▼
Phase 3  写作 + check_doc
        │
        ▼
Phase 4  独立 reader 验收
```

依赖规则：

- R 需要先知道入口 → 等 S 的相关切片，不等 S 全部做完。
- R 不需要源码地图 → S 和 R 可以直接并行。
- D 是“宣称清单”，不是实现证据；能验证的用 S 或 R 核对，不能验证的标“未验证 / 仅文档”。
- 同一对象的多个访问面可以并行，但证据标签必须分开，不能互相顶替。

## 5. 发几个

以下是建议值，不是报告契约：

| 范围 | 建议 worker 数 | 说明 |
|---|---:|---|
| 第 1 幕 进入 | 0–1 | 单链；多个独立访问面才按面拆 |
| 第 2 / 4 / 5 幕 | 合计 0–1 | 安装后、承载者、横切需要统一口径 |
| 第 3 幕 核心链路 | 2–4 | 按独立功能 / 状态节点拆 |
| 独立 reader | 1 | 报告写完后启动 |

并发建议 3–4；单次调研 worker 总数建议 ≤6。超过先把问题合并，不要继续加人。

## 6. Worker packet

每个 worker 只拿一个包，一包一问：

```text
任务：<一个可验证问题>
对象：<repo@commit / URL / app>
通道：S 源码 / R 运行时 / D 文档
允许：<只读命令 / 导航 / 截图 / 读文件>
禁止：写对象、写报告、改配置、发消息、给最终结论
输出：
- 结论：<一句，标 已验证 / 未验证>
- 证据：<path:line | 截图 | 命令+输出>
- 反例/失败路径：<...>
- 未验证：<...>
```

约束：

- 只读；只继承 L0/L1，L2 必须由主 agent 按本次授权逐次确认，L3 永不执行。
- 证据路径相对仓库根；截图给固定编号，不复制多份。
- 不把另一个 worker 的结论当输入；需要交叉时由主 agent 转发证据，不转发结论。
- 不写报告段落；主 agent 统一改写和合并。

## 7. 主 agent 对账

worker 说“已验证”不等于已验证。主 agent 必须：

1. 对每条关键结论复核源码引用或重跑实测，**100% 覆盖，不抽查**。
2. 检查引用是否指向真实文件、真实行号、真实行为；指不回就删除或标“未验证”。
3. 不同驱动的证据分开保留：截图不能证明 DOM，API 不能证明界面，源码不能证明 UX。
4. 冲突时回查源码或重新实测，不靠投票，也不靠 worker 之间的共识。
5. 不直接复制 worker 的行文；用报告自己的语言重写，保留证据。
6. 数字重新核对口径、尺子、分母、时刻。

## 8. Reader handoff

报告写完、`check_doc` 结构通过后，再启动独立 reader：

- 第一段：只给决策简报，回答 Q1–Q7。
- 第二段：只给第 1–5 幕，复述 M1–M5。
- 第三段：给一个功能档案 + 证据附录，复述 F1–F3，并圈出不懂的词。
- 不给源码、不给仓库路径、不给对话记录。
- reader 返回 `[读者验收]`；主 agent 写进 `appendix-selfproof`，答不出先改报告。

## 9. 按 SOP 级别

| 级别 | 典型独立单元 | 建议编排 |
|---|---|---|
| A 产品能力 | 入口、功能、访问面 | 单主 agent；≥3 个独立功能簇或 ≥2 个访问面才拆 |
| B 技术机制 | 模块、调用链、失效路径 | S 按模块并行；R 实验串行；主 agent 合并 |
| C 对比 / 选型 | 每个对象 | 每个对象独立分诊；对象间并行；同一把尺子 |
| D 外部方案 | 源码 / 文档 / 小实验 | S/D 取证；座位判断由主 agent 做；实验串行 |
| E 失败复盘 | 时间线、issue/PR、版本 | S/D 可按时间段或主题拆；时间线由主 agent 统一重建 |

## 10. 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 按幕号平均发 | 第 1 幕被过度拆，第 3 幕不够细 | 按独立证据单元拆 |
| 运行时链并行 | 登录/状态/数据互相污染 | 同一状态链串行 |
| worker 直接写章节 | 文风、口径、结论分裂 | worker 只回证据，主 agent 写 |
| worker 互传结论 | 电话游戏，证据链断 | 只由主 agent 转发证据 |
| 先派发后探针 | worker 猜访问面，产出不可用 | 先分诊再派发 |
| 把 worker 的“已验证”当已验证 | 错误结论进报告 | 主 agent 100% 复核 |
| reader 参与调研 | 自己验自己 | reader 只做验收 |
| 多个 worker 改同一文件/状态 | 冲突和覆盖 | 一个证据单元一个 owner |
