# Unslop

unslop 由 Damir Sokolovsky（[@heydamir](https://x.com/heydamir)）创建，他在 X 上发起了 Unslopping 系列。它采用 CC BY 4.0 许可，所以在任何副本或改编版本中都要保留这段署名。

**本地已修改。** 触发描述已收窄到已经存在的界面，因此本技能与 `cc-design-taste-frontend` 不会同时触发（2026-11-05，agent-home fork）。这个文件里的其他内容没有改动。

**适用边界。** 本技能需要一块已经跑起来的屏幕——源码文件、线上 URL 或一张截图——并且它会保留内容、结构和技术栈。如果页面还不存在，或者决定丢掉当前布局重新构图，就停下来改用 `cc-design-taste-frontend`；不要把这次运行硬撑到覆盖一次从零构建。

Vibecode 出来的 UI 总是以同样几种可预测的方式失败。每个表面都在发光，每个标签都带一个 emoji，间距是模型当天随手敲出来的，文案在喊。unslop 修的是手艺，产品本身留着。功能、内容和区块顺序不动。变的是每一个尺寸、颜色、用词和图像都成了有意的选择。

去掉 slop 只是一半工作。一块干净但可能属于任何产品的屏幕，就是下一个模板。每次运行结束时，得到的应该是一块只有这个产品才可能有的屏幕。

slop 和手艺的差别在于丰厚感放在哪里。slop 把颜色和效果铺在外壳上——背景、按钮、边框和标签。手艺让外壳保持安静，把丰厚感放进一两个人们会记住的内容时刻里，比如一个渲染出来的物体、一张漂亮的图表，或一张来自这个产品所属世界的图像。

像设计师做红线圈注（redline）那样工作，一层一层地过，覆盖整块屏幕。

## 好的标准

- **一个明亮的元素。** 每块屏幕都有一个被打磨过的东西来承载颜色和手艺：一个渲染出来的物体、一幅绘制出的场景，或一张信息量丰富的图表。它周围的一切都安静，所以一眼就能读懂。
- **安静的外壳。** 导航、按钮和文字使用带色调的中性色加一个强调色。没有东西发光，没有东西去和那个明亮元素竞争。
- **一个清楚的想法。** 你能用一句话说清这个视觉展示了什么，以及它为什么属于这个产品。
- **文字落在安静的空间上。** 标题坐在图像或布局中为它留空的那块区域上，简短且具体，配一个主操作和一个次操作，下面不再堆任何东西。
- **真实的产品，真实的材质。** 预览看起来像真实的应用，数据可信；物体看起来像真实的东西，有重量、光和影。

哪些视觉风格通常有效、哪些会失败，见 [references/visuals.md](references/visuals.md)。可以学习的成品示例在 [references/refs.md](references/refs.md)，像用字符绘制图像这类代码处理手法在 [references/effects.md](references/effects.md)。

## 运行流程

1. **看这块屏幕。** 找到渲染它的文件。如果你能跑起应用，或在浏览器里打开文件并截图，就去做，这样你判断的是人们看到的东西，而不只是代码。
   - 只有线上站点的链接、没有代码？用 `node <skill folder>/scripts/snapshot.mjs <url> unslop/original.html` 把页面保存下来，然后在这个文件的副本上工作。加上 `--dark` 或 `--light` 以匹配用户看到的主题。它还会保存 `original.live.png`，即线上页面的截图，所以先渲染保存下来的副本，把两者对比之后再动手。由脚本绘制的动画背景不会保留下来，因此在审计中根据线上页面描述它们。
   - 只有一张截图？先把这块屏幕重建为一个静态 HTML 文件，尽量贴近原样，并把它当作原始版本。
   - 这两种情况下，结果都是一份用代码重新设计的页面，用户可以把它交给真正站点的负责人，所以要在报告里说明这一点。
2. **审计。** 过一遍 [references/signs.md](references/signs.md)，把你发现的每个迹象都列出来，每条一行，并注明它在哪里。
3. **决定改多少。** 在规划任何东西之前，先诚实地读一遍审计结果。
   - **重度 slop**，颜色、字体、图标和文案上都有很多迹象。跑下面完整流程。
   - **轻度 slop**，一块大体上已经设计过、只留下几个迹象的屏幕。打磨模式。只修审计发现的东西，方向从已有品牌里取，而不是新编一个，并保留配色、字体、布局和视觉。更大的想法——比如缺了一个时刻，或给 hero 配一个场景——写进报告作为建议，而不是当作改动。
   - **没有 slop。** 直接说出来，最多提两三个小改进，给出确切数值。只有在用户同意时才应用，然后就停在那里。绝不要仅仅为了让它不一样而去改一块好屏幕。
4. **定方向，然后停下。** 写下下面描述的五句短句。把审计和方向给用户看，等他们答复后再动手编辑，因为之后改方向意味着全部重做。如果你有向用户提问的工具，就用它提问；否则用纯文本提问，然后停下。只有当用户已经说过直接做时，才跳过等待。
5. **按顺序分九轮修复。** 一轮要在整块屏幕上做完，再开始下一轮。当几乎每一行都要改时，先按顺序规划好各轮，然后一次性写出新屏幕，只要每一轮都落实了。间距最先，因为节奏一旦对了，其他一切读起来都不同。文案在字体和布局之前，因为标题的长度决定它的字号和它坐在哪里。视觉和动效最后，因为它们应该适配一块在没有它们时已经能用的屏幕。
6. **检查。** 跑本文件末尾的检查清单，重新渲染并与审计清单对比。清单上仍然存在的东西都要修掉。
7. **报告**：方向、每轮改了什么（每轮几行），以及你写过的任何图像提示词。
8. **录制——当被要求，或用户想要一个可以分享的东西时。** 构建故事文件，并渲染 [故事影片](#故事影片) 中描述的影片。如果用户一开始就要求了，就在推进过程中把每一轮写进故事文件。

让一次运行尽量快。为了检查而渲染屏幕最多三次。生成图像时，在方向一确认后立刻开始生成，并在它运行期间继续做前几轮，而不是等它。

每一轮的确切数值在 [references/tokens.md](references/tokens.md)。

## 方向

在动任何东西之前，写下五句短句。从页面对“产品做什么、给谁用”的表述里推导出它们。绝不从什么正在流行来推导。

- **产品。** 它做什么、给谁用，一句朴素的话。
- **性格。** 两三个具体的词，比如 `calm, exact, a little warm` 或 `fast, technical, playful`。clean、modern、sleek、minimal、premium 这类词不允许，因为它们描述的是每一个模板。
- **世界。** 这个产品天然所属的场所或材质。笔记应用靠近纸与墨，监控工具靠近仪表与夜班，旅行应用靠近地图与窗光。这个世界决定中性色的色调、强调色和视觉。
- **时刻。** 一两个让屏幕获得丰厚颜色、材质和细节的地方，从产品所展示的内容中挑选。可能是预览里一张渲染出来的卡片或设备，一张每种颜色各代表一个系列的图表，一个来自那个世界、被放在内容旁边的物体。写清它们是什么。
- **签名细节。** 一个只有这个产品才会有、并且一贯使用的小细节。监控工具的一个实时状态点，开发者工具的键帽，教学应用的手绘下划线，配送应用的路线。一个细节，不是五个。

这里的例子只展示一个答案的形状。即便某个例子碰巧合适，也要从你面前的产品推导出你自己的。

如果产品已经有真正的品牌，比如一个 logo 文件、一个颜色或一款并非 slop 的字体，就保留它，并围绕它建立方向。紫到蓝的渐变、星光和辉光即使在 logo 里也是 slop，所以除非用户说它们是品牌，否则不算作品牌。

## 1. 间距

- 一切都在 4px 网格上。外边距、内边距、间隙和固定高度都是 4 的倍数，所以 28 或 104 是可以的，即使它们不在 token 列表里。2px 的步进用于小控件内部的微调是可以的，而一个恰好能让某物居中的奇数值可以保留。
- 同类同尺寸。列表里所有行共用一个高度和一个间隙，一行里的所有卡片共用一个内边距。
- 空间体现分组。组内空间小于组间空间，这样列表读起来是一整块，各区块读起来是分开的。
- 东西要对齐。图标站成一列，标签从同一条线开始，数字在一列内右对齐。没有任何东西被一个游离的 translate 或奇怪的外边距推出这条线。
- 内边距跟随密度。紧凑面板和侧栏大约 16，卡片 20 到 24，页面边缘 24 到 32。
- 导航是应用里最密的部分。行高 32 到 36，行间 2 到 4，图标一列，标签一行。分组标签离它自己的条目要比离它上方的分组更近，比如上方 24、下方 8。这一轮做完后量一下侧栏，间距最常在这里崩。
- 去掉破坏节奏的一次性数值，比如 `mt-[13px]` 或 `py-[11px]`，换成比例尺上的档位。

## 2. 色彩

- 从一条中性色阶构建，按方向朝那个世界着色。从 token 里挑 graphite、warm 或 ink，或者用同样的方式给自己的色阶着色。背景、抬起的表面、边框和文字都来自这条色阶。
- 在应用和仪表盘里，背景、表面、边框和文字保持中性，即 graphite 色阶或同样灰的东西。人们一连看它们几个小时，颜色必须由内容来承载。一块背景读起来是橙、棕、蓝或绿的屏幕已经过头了。那个世界体现在强调色、图表和时刻里，不在表面里。落地页可以把表面进一步朝那个世界着色。
- 三种文字角色：主、次、弱。不是十种略有差别的淡紫色。
- 在外壳里，一个强调色，用得少。它标记主操作、选中状态，或那个唯一要紧的数字。
- 方向里的那些时刻是例外。在它们内部颜色可以丰厚：一张图表里有多个色相，一个用真实材质渲染出来的物体，一张自带光线的图像；只要它仍待在那个世界之内，并且每种颜色都有意义。
- 如果品牌有真正的颜色，它成为强调色，并从表面上退出去。如果没有真正的品牌色，就从那个世界里取强调色。
- 强调色上放文字要达到 4.5 比 1 的对比度。达不到就把它调暗，或在上面放深色文字。强调色作为文字或墨色用在浅色表面上时需要同样的对比度，所以在那里用它更深的一档。
- 在深色主题里，主按钮可以是色阶里的一个偏白，配深色文字，强调色则可以住在更小的位置，比如选中状态或一个关键数字。这常常比一个上色的按钮看起来更有意为之。
- 语义色只承载含义，比如绿色表示好的变化、红色表示错误，并且它们被压低到能坐进配色里。
- 去掉表面上的色相渐变、渐变文字、带颜色的辉光和带颜色的阴影、内容背后的径向色晕和色块，以及霓虹边框。
- 边框是安静的发丝线，取色阶里的文字色，6 到 10% 不透明度。
- 在深色主题里，深度来自表面层级和发丝线，不来自阴影。浮在图像上的窗口或物体可以保留一层柔和的中性阴影。在浅色主题里，阴影是中性的、柔和的、小的。
- 渐变只允许作为单个中性色内部的小幅色调变化，比如激活行从 #2b2b2b 到 #1f1f1f。绝不从一个色相到另一个色相。

## 3. 图标

- 每一个用作图标、或在标签里作装饰的 emoji，都变成同一套里的线性图标。用项目已经有的那套，否则用 lucide。
- 处处一个尺寸、一个描边，16 或 18px，配 1.5 描边。
- 图标取它所属文字角色的颜色，通常是次级或弱化。它们从不会有自己的颜色。
- 图标盒在每一行宽度相同，到标签的间隙固定，8 或 10，这样标签能对齐。
- 去掉什么也没增加的图标，比如每个卡片标题里、或每个分组标签前的 emoji。需要颜色的分类给一个小状态点。

## 4. 文案

- 标题用朴素的话说清产品为谁做什么，以至于它们套不到另一个产品上。使用页面上已有的事实，不要新编。
- 界面文字里不用感叹号，也绝不用 `!!`。
- 不要 `Welcome back, Damir! 👋` 这类问候式标题。标题点明上下文，比如页面名称或时间段，例如 `October 2026`。
- 标签要短。用 `Search`，不用 `Search anything...`。
- 一个变化要说明它对比的是什么，比如 `+12% vs last month` 或 `3 fewer vs last month`。
- 标题、副标题、标签、按钮和说明文字结尾不加句号。只有由多个句子组成的段落保留句号。
- 不用 supercharge、seamless、unlock、magic、revolutionize 或 game-changing 这类浮夸词，也不要什么上面都挂 `AI-powered`。
- 无法核实的说法，比如 `Loved by 10,000+ teams` 或 `10x faster`，如果用户确认它们是真的，就改成安静而具体的表述，否则删掉。要问，并把它们列进报告。
- 模拟数据要看起来是真的，数字和名字可信，绝不用 `[X]` 或 `123,456`。
- 像 `PRO`、`New ✨` 或 `Beta 🚀` 这样的徽章要去掉，除非产品确实需要，那就把它们做成安静的文字。

## 5. 字体

- 按方向里的性格选字体，从 token 里的字族中选。当项目字体是真正品牌的一部分时保留它。像 Inter 这种没人选过的默认字体，在有更贴合性格的字族时可以换掉。界面用一个字族，加上最多一个来自 token 任意一行的搭配字体：等宽用于数字和元信息，或展示体用于大标题。
- 从比例尺里取几个字号，两个字重，400 和 500，最多 600 用于少见的强调。不要 700 到 900 的标题，不要渐变文字。
- 层级来自字号和颜色，不来自字重。
- 处处使用句首大写（sentence case）。像 `NAVIGATION` 或 `PAID THIS MONTH` 这种字距拉得很宽的标签，变成 `Navigation` 和 `Paid this month`。
- 小字永远不用负字距。小字上的可读性意味着更大、稍重或稍松。紧字距只用于大号展示文字。
- 数字使用 `tabular-nums`，整块屏幕一个格式。如果一个数字是 `$48,210`，下一个就不是 `$124,860.40`。
- 不用斜体做强调。

## 6. 布局

- 保留区块及其顺序。在区块内部，如果能让屏幕更清楚，对齐方式和比例可以改。
- 应用和仪表盘保持真实应用的尺寸比例。外壳填满视口，侧栏 240 到 280，内容自适应，通常上限在 1440 到 1600 宽，页面长度随它的内容而定，首屏下面还有更多区块。绝不把一个应用缩成居中的窄栏。如果原图是画在背景板上的一个小窗口，就让它看上去仍然是一个窗口，带上窗框和背景板，同时内部仍给桌面端的比例。
- 最强的落地页 hero 是一个场景。一张生成的图像从边到边填满 hero，它的主体坐在一侧，标题坐在同一张图像安静留白的那部分上，产品视图从底边升起。去看参考里的 hero，就知道它是什么样。
- 没有场景时，用不对称分栏：文字在一侧，视觉至少占一半宽度；或者文字在上，下面是一个大的产品视图。所有东西堆叠居中就是模板的默认做法，只有在没有视觉的短 hero 里才保留它。
- 在场景式 hero 里，文字块坐在上半部分，即导航与产品视图顶部之间的那块空间里，位于它的视觉中心，比真正的正中稍高一点。
- 在分栏里，把文字块相对视觉垂直居中，这样两侧都不会留下一个大空角。如果视觉高得多，就把它缩短，而不是把文字往下推。文字旁边漂浮的卡片和设备很难平衡，优先用一个完整的视觉。从导航到标题的间距 token 适用于堆叠式 hero，分栏式 hero 则是居中。
- 长标题左对齐。居中对齐适用于一到两行短文字。
- 一个主操作，旁边最多一个次操作。其他任何东西都移出 hero。
- 导航保持安静。Logo、已有的链接、一个按钮。登录是旁边一个安静的文字链接，不是第二个按钮。不要求悬浮胶囊式头部。在小屏上，链接收拢成一个菜单按钮。
- 把首屏当作一个整体来构图。hero 填满视口高度，不留一条死的空白带。如果内容偏短，就把它居中，或者让产品视图从较低处开始并超出底边，让页面有向下滚的邀请。
- 在小屏上，所有东西按阅读顺序堆叠，标题降到 token 里的移动端字号，视觉排在操作之后。密集的预览在移动端变得更简单，行列更少，而不是被整体缩小。里面的文字不低于 11px。

## 7. 细节

- 嵌套圆角。内圆角等于外圆角减去两者之间的内边距，且不小于 4。控件 8 到 10，卡片 12 到 16，面板 14 到 20。不是所有东西都是胶囊。
- 计数和元信息变成安静的文字，常常是弱化的等宽字，而不是发光的胶囊。
- 键盘快捷键变成小键帽。
- 图表落在弱化的网格上，配弱化的等宽标签。一个系列内部不要彩虹色柱，不要发光柱，不要大写日期标签。如果图表只是占位噪声，换成能讲真事的数据。
- 图表像文字一样有层级。一张主图明显是屏幕上最大的东西，画得用心，比如平滑的线或镜像对比。其他任何展示数据的东西都更小、种类也不同，比如带细条的排名列表或一张短表，绝不是第二张同样大小的图表。
- 每张图一个强调色。要紧的那个东西——比如当前月份、你在跟踪的那条线，或增长了的那个方案——拿到强调色，其他一切坐在色阶的中性层级上。只有当图表真的必须区分系列时才用多个色相，即便那样也是一个主导、其余安静。
- 统计卡片就是数字。一个标签、一个大数字，以及一个带对比对象的变化。不要加迷你折线、计数记号、迷你柱或图标来填满它们，那些读起来像装饰。当卡片计数的正是某件实物时，卡片里可以放一个看起来真实的物体，比如已支付收入旁边的付款收据，或支出旁边的银行卡。该仪表盘需要多少张就用多少张，只要每张都能独立读懂，且没有一张是迷你图表。
- 尺寸要有变化。等宽并排、内容同类的卡片读起来像模板。给网格一个节奏，比如一行三四个紧凑统计放在一张宽图上方，或一张宽图旁边一条窄列表。
- 按数据选图表类型。趋势用折线，对比用柱，占比用一根堆叠条或带条的列表，单一目标用进度条。
- 激活态是一次很小的表面层级变化，加一条发丝高光，不是带辉光的渐变。
- 悬停和聚焦状态要存在，并留在配色之内。给键盘用户一个可见的聚焦环。
- logo 就是主字族里的产品名，如果有的话再加一个简单标记。不要渐变字标，不要星光方块。
- 方向里的签名细节出现在它该出现的地方，别处不出现。

## 8. 视觉

- 装饰性填充物去掉。光亮色块、球体、星云、漂浮方块、发光网格、全息大脑和机器人，对产品什么也没说。
- 落地页 hero 要配一个展示出真实东西的视觉。
- 仪表盘和应用屏幕几乎从不需要生成的图像。它们的时刻来自产品本身：一张用心绘制的图表、排得漂亮的数字、像产品照或头像这样真实的内容、一个感觉是活着的状态。产品所处理的实物——比如金融应用里的支付卡——通常更适合用代码构建，配上真实材质、柔和渐变、芯片、一个卡号。
- 为应用生成图像只用于空状态、引导流程和营销时刻，或用户要求时。
- 有图像生成工具时，落地页 hero 的首选是方向里那个世界的一个场景，生成得足够宽，能垫在整个 hero 后面，并在文字要放的地方留出安静的空白。它承载颜色和氛围，外壳在它之上保持安静。
- 在场景下面，或者在没有工具时作为视觉，展示产品。用代码做一个页面已经承诺的东西的预览，用项目的组件或仔细写就的 HTML 加可信的数据，比如主界面、一张关键卡片，或产品产出的结果。展示文案已经声称的东西不算发明功能。在场景式 hero 里，它从底边升起并超出底边。
- 产品视图要承载一个时刻，而不只是一张朴素的卡片。里面一个渲染出来的物体，比如数字上的一张支付卡、一张信息量丰富的图表，或一个来自那个世界的小物件。这些是物体的种类，所以用一个合适的没问题。
- 在这一轮之前，看 [references/refs.md](references/refs.md) 里的参考。从它们身上取品质，比如构图、光线、克制，以及时刻被放置的方式，绝不取它们的主题或布局。
- 渲染物体和场景，在有图像生成工具时来自工具。如果没有，能用代码构建的就用代码构建，其余的写好提示词，并留下尺寸合适的空位。
- 怎么选主体、提示词配方，以及怎么放置这张图像，都在 [references/visuals.md](references/visuals.md)。这一轮之前先读它。

## 9. 动效

- 去掉毫无理由循环的动效，比如用在非实时内容上的 `animate-pulse` 或 `animate-ping`、标题上的微光扫过、呼吸式辉光、漂浮元素和视差。
- 去掉 `transition-all`、弹性弹簧、卡片上的 `hover:scale`，以及任何在悬停时移动超过几个像素的东西。
- 保留能解释东西的动效。悬停是一次快速的颜色或表面变化，按下是一次微小的缩小，菜单从它打开的位置淡入并升起几个像素，变化的数字做补间。
- 过渡 color、background、border、opacity 和 transform，并写明它们，比如 Tailwind 里的 `transition-colors` 或 `transition-[transform,opacity]`，而不是用一个万能写法。绝不对 width、height、top、left、margins 或大幅模糊做动画，它们在弱设备上会卡顿。
- 整块屏幕一条缓动曲线、少数几个时长，取自 token。反馈要短，入场的东西稍长一点。
- 加载时最多一个入场：主内容一个短的淡入升起，带一点错开。不是每张卡片都从不同方向飞进来。

## 故事影片

一支短视频，屏幕在其中一步一步地把自己 unslop 掉，slop 上带红色的红线圈注。构建之前先看 [refs/story-dashboard-frames.webp](references/refs/story-dashboard-frames.webp)，按顺序看其中的八帧。那支视频火了，它的做法是这样：

- **什么都不替换，一切变形。** 一个页面，每一步只改 CSS，所以内边距、间隙、尺寸、颜色、圆角和阴影都就地补间到新值。你能看到间距撑开、紫色褪去、圆角变柔。
- **波次。** 元素从左上往下每隔几十毫秒依次开始，于是一个变化扫过屏幕，而不是所有东西同时翻转。
- **文字滚动。** 发生变化的文案模糊淡出，新词逐字升起。
- **先红线圈注。** slop 带上带标签的红色选框，间距那一轮显示红色尺寸标注，修好之后变成白色，细节那一轮描出各个圆角及其半径。
- **近、短。** 方形，紧贴变化最大的那部分裁切，这样在手机上也能看清，长度约 10 秒。

它会多花几分钟，所以只在用户想要时做。

1. **一个故事文件。** 构建 `unslop-story/story.html`，它是原始屏幕的独立副本，样式写在文件里。原始规则保持原样，它们是第 0 步。
2. **步骤。** 三到五步，把几轮合并，使每一步都改变你能看见的东西，比如 `Spacing`、`Color and icons`、`Type and copy`、`Details`。新的图表或视觉放进最后一步。在 head 里把它们列出来：`<meta name="unslop-steps" content="Spacing, Color and icons, Type and copy, Details">`。名字里含 Spacing 的会显示间距测量，含 Details 的会显示圆角轮廓。
3. **每一步是叠加在上面的 CSS。** 把第 1 步的改动写在 `.s1` 下，第 2 步写在 `.s2` 下，以此类推，比如 `.s1 .card { padding: 24px }` 或 `.s2 body { background-color: #141415 }`。这些类会累积，所以第 3 步仍然带着第 1、2 步的规则。改的是值，绝不是结构，这样浏览器才能补间。
4. **不能补间的东西，以及怎么处理。**
   - 渐变、辉光和色晕：把它们放在单独的一层上，把它的 `opacity` 淡到 0，同时底下的纯色在变。渐变文字只放在 `.from` 的 span 上，绝不放在 swap 或它的父级上，因为文字裁切也会把隐藏的新文字一起裁进去。
   - 胶囊：把它们的圆角写成高度的一半，比如 `23px`，不要写 `9999px`，否则圆角只会在最后一帧才变化。
   - 少用 swap，只在词发生了变化的地方用，一个故事里最多八处。二十处 swap 同时模糊，读起来像两张图之间的硬切，而这正是视频绝不能看起来的样子。字重、字号、字距和颜色的变化自己就会补间，所以从不需要 swap。新的字族在它那一步直接切换，不用 swap。
   - 会变的文字、新的字族、变成图标的 emoji：`<span class="swap" data-at="3"><span class="from">Welcome back, Damir! 👋</span><span class="to">October 2026</span></span>`。到第 3 步，旧的部分模糊淡出，新的部分滚入。
   - 变成图标的 emoji：把新图标放在同一个盒子里、紧挨着 emoji，两者都绝对定位叠在一起，在这一步里交叉淡化它们的 `opacity`。这不算 swap，也不计入上限。
   - 会消失的东西，比如 `New ✨` 徽章：`data-out="2"` 让它们在第 2 步收起。
   - 会出现的东西，比如图例：`data-in="4"` 让它们在第 4 步淡入。预留它们占的空间，这样不会有东西跳动。
5. **红线圈注。** 测量会实时跟随元素，所以它们的数字在东西移动时从旧值数到新值。那正是人们盯着看的时刻，所以要选好它们。
   - `data-gap` 标在纵向堆叠的各个块上，比如侧栏里的品牌行、搜索、导航组和套餐组，或主栏里的标题、统计行和图表。不要标在每一行上，否则屏幕会塞满 2px 的小标签。每个堆叠做四到六处测量间隙，如果有多个堆叠，给每个起自己的名字，比如 `data-gap="sidebar"` 和 `data-gap="main"`。
   - `data-radius` 标在两到四个圆角会变的按钮和卡片上。
   - `data-slop="Gradient text"` 之类的标注在开头短促的一拍里标出 slop，最多五处，用彼此分开、最清楚的例子，配短标签。这是可选的，参考视频里没有。
6. **只有屏幕和它的背景。** 视频按故事页本来的样子展示，周围没有多余的窗口、边框或阴影，所以页面自己的背景填满画框，屏幕是唯一的盒子。如果屏幕坐在一个会长到桌面比例的窗口里，就在故事里把它锚定在左边，让它向右变宽，而不是横向滑动。故事页渲染为 1440 宽、至少 900 高，所以不要用 `100vh` 来定尺寸，`position: fixed` 只留给背景层。
7. **镜头。** `<meta name="unslop-frame" content="0 0 960">` 设定页面的哪一部分填满画框，以页面像素给出 x、y 和宽度。把 x、y 指向屏幕自己的左上角，这样画框从它周围的页面背景开始，并紧贴变化最明显的地方裁切，通常是侧栏或标题加上最前面几张卡片。
8. **渲染。** `node <skill folder>/scripts/story.mjs unslop-story/story.html unslop-story.mp4`，默认方形，`--wide` 为 16:9。它需要 Playwright 和 ffmpeg，缺哪个就告诉用户装它的那条命令。想先实时观看，就用 `--play` 代替输出路径运行，它会在浏览器窗口里循环，直到被关闭。交付之前用 ffmpeg 抽几帧看看。检查故事文件和视频不计入一次运行的渲染上限。
9. **故事文件是一件演示作品。** 干净的结果仍然以正常代码、用项目自己的技术栈交付，不带 `.s` 类和故事属性。每支视频都带一个小小的 `unslop by @heydamir` 署名，这是许可要求的。

## 不要做

- 不要给产品改名，即使名字里带 AI。真正的 logo 保持原样。当 logo 本身就是 slop，比如一个 emoji 或渐变方块里的星光，就把它重画成平的：只用新字体里的字标，或用产品想法里的一个简单符号、单一纯色。绝不要光泽球或渐变球、辉光或渐变方块，那些第一眼就读作 AI。
- 不要改变产品是什么。保留它的功能、内容和区块顺序，除非用户要求更多。毫无意义的占位内容可以换成有意义的内容。
- 不要用新的装饰替换掉已移除的装饰，也不要用一个潮流换另一个潮流，比如玻璃、颗粒、噪点、霓虹或便当格布局。
- 不要编造功能、说法或数据。
- 不要给每个产品都退回同一套外观。决定配色色调、字体和视觉的是方向，不是习惯。
