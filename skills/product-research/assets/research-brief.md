# 调研简报（开工前写，只问一次）

> 整场调研只会停下来提问一次。只有下面三种情况需要问：① 决策句推不出；② 会花 LLM 额度或往对象侧写盘（写你自己的报告不算）；③ 产出位置/形态有歧义。其余情况写完简报直接开工。

## 1. 决策句

这份报告要回答谁的什么问题？

```
我们准备 <做什么决定>，需要知道 <对象的什么>。
```

例：我们准备把三个上下文插件合并成一个产品，需要知道三者各自的能力边界、互相冲突点，以及合并后谁负责什么。

## 2. 对象

| 项 | 值 |
|---|---|
| 名称 | |
| 版本 | |
| 证据来源 | 上游 tag / 本机安装 / 线上环境（含 URL） |
| SSOT 声明 | 以哪个为准（安装副本与上游不一致时怎么处理） |

## 3. 访问面

| 项 | 值 |
|---|---|
| 形态 | Web 页面 / 桌面 App / CLI / API / 混合 / 自家生态 |
| 驱动 | browser-use / computer-use / 终端 / curl |
| 探针 | 通过 / 失败 → 降级为（手工截图 / 只看源码 / 只看文档） |
| 备注 | 登录、权限、平台差异 |

> 一个产品可能有多个访问面：先选用户主路径那个，其余作补充证据（见 `references/access-surfaces.md`）。

## 5. 操作许可

## 6. 起点与停止

- 起点级别：A / B / C / D / E
- 打算走到哪一级、为什么（到"能判断"即可）
- 什么情况下不往下走（成本、无权限、证据已够）

## 7. 产出

| 项 | 值（默认） |
|---|---|
| 形态 | **单文件自包含 HTML**（截图以 data URI 内嵌，不产出 shots/） |
| 位置 | `<workspace>/.research/<slug>/<YYYY-MM-DD>-v<N>.html`（用户指定则从指定） |
| 版本 | `<N>` = 该对象已有报告数 + 1（读 `.research/<slug>/index.json`）；**永不覆盖旧报告** |
| 既往调研 | 首次 / 第 N 次（有则列出上一版日期与结论，本次必须写「本版变化」） |
| 语言 | 中文 |
| 视觉 | 结构用 skill 基线；皮肤取自被调研对象的 UI（背景 / 面板 / 主色 / 字体气质） |
| 报告骨架 | 前置结论卡 + 固定九段 + 附录（`report-kernel.md`） |
| 机器可读 | `<script id="report-meta">` + `index.json` |

## 示例（已完成的调研，可参照）

```
1. 决策句：我们要把三个上下文插件合并成一个产品，需要知道三者能力边界、
   互斥点，以及合并后谁负责什么。
2. 对象：三个插件，版本与本机安装一致，SSOT = 上游 tag。
3. 访问面：Web 页面 / browser-use / 探针通过（能列出页面并打开 3080）。
4. 证据：可运行实例、源码、文档、issue 均有。
5. 许可：L0 + L1；L2/L3 全面禁止（用户明确：不许删除 context）。
6. 起点 A，走到 C（要合并）；停止条件：能回答"要不要合、谁干什么"。
7. 产出：单文件 HTML（截图内嵌），落 .research/<slug>/<日期>-v1.html；index.json 登记；交付后问一次清理。
```
