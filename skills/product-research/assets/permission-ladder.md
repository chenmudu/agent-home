# 操作许可分级

调研对象不是试验田。默认只读，写操作逐级审批。

| 级别 | 动作 | 默认 | 需要 |
|---|---|---|---|
| **L0 浏览** | 打开页面、切标签、看列表、滚动 | 允许 | — |
| **L1 无害交互** | 筛选、排序、展开折叠、打开详情弹窗、切换视图、刷新 | 允许 | — |
| **L2 可逆写入** | 新建测试项、改自己的设置、开关可撤销的选项 | 禁止 | 每次单独确认；确认后立刻验证可撤销 |
| **L3 不可逆** | 删除、发布、扣费、改共享状态、改全局配置、清空日志 | **永不执行** | 只能由用户手动完成 |

## 每次点击前的三问

1. 这一步**写**吗？（只读 → 放心点；写 → 进第 2 问）
2. 写到**哪里**？（只在本地/我的账号 → 可能可逆；影响共享状态 → L3）
3. 能**撤销**吗？（不能 → 不点，除非用户当场明确授权）

答不出这三问，就不要点。

## 破坏性按钮的正确用法

- 可以打开确认弹窗，**看它说什么**（文案、代价、是否提示不可逆），然后取消。
- 不要为了"验证守卫"去真的执行一次。
- 如果必须验证拦截逻辑，用**已存在的保护条件**（例如会话运行中）而不制造破坏。

## 驱动相关的额外风险

| 驱动 | 额外风险 | 对策 |
|---|---|---|
| **浏览器** | 标签所有权只在当前回合有效；跨域 iframe 读不到；登录墙 | 每回合重新取标签；iframe 用 `frameLocator`；登录让人工接管，不要索取凭据 |
| **computer-use** | 点位是盲的：窗口被遮挡、DPI 缩放、多屏坐标都会点偏；会点到别的窗口 | 点前先截图确认坐标；破坏性按钮（删除/发布/支付）一律不点；必要时 `requestManualHandoff` |
| **终端** | 命令可能写盘、改环境、装依赖 | 先 `--help`，优先 dry-run / 只读子命令；不在目标仓库里执行会写文件的命令 |
| **API** | 一次调用可能扣费、写数据、触发后台任务 | 先打只读端点；花钱的调用要单独确认；记录调用次数 |

同一条结论如果来自不同驱动，**分别标注**（`[浏览器]` `[屏幕]` `[终端]` `[API]`），不要合并成一句"实测"。

## 非变更自证（收尾必做）

在报告第 2 段写清：

```
操作区间：<开始时间> → <结束时间>
写操作：0 次（或：L2 共 N 次，均已撤销）
外部调用：<哪些操作花了钱 / 额度>
被改动文件：<路径 + mtime>（没有就写"无"）
自证：<关键计数/合计/行数> 开始 = 结束（截图 a / b）
```

**L1 也可能落盘。** 只读交互会触发缓存、索引、日志、缩略图等副作用。收尾时对比目标目录与数据目录的 mtime；发现了就如实列出，并说明它是否影响只读结论。

没有自证，"我只看了看"就只是一句承诺。

## 授权边界

- 用户的授权**只覆盖本次、本条**，不自动延续到下一次。
- 用户说"你自己判断"时，判断范围仍限定在 L0/L1；要升到 L2 必须再问一次。
- 一旦发现对象状态已被别人改变（数据不一致、出现陌生写入），停下来说明，不要当成自己的操作结果。
