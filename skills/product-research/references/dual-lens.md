# 双镜头：产品读法 + 开发读法

一条发现只在一个镜头里成立，说明还没查透。两个镜头都落地，才算一条结论。

## 产品镜头（五问）

1. **谁**在什么场景下用它？
2. 他**看到**什么（首屏、列表、按钮、提示）？
3. 他**得到**什么（省了什么、多了什么能力）？
4. 他**付出**什么（时间、钱、风险、不可逆动作）？
5. 他**被骗**了吗（宣称存在但界面没有；界面有但没实现）？

坏答案长这样："提供上下文管理能力。"——没有谁、没有场景、没有代价。

好答案长这样："运行中的会话里，用户点 `>5k` 档筛选后可以一键全选可见条目再删除；代价是不可逆，且删完必须重新跑一遍模型。"

## 开发镜头（五问）

1. 靠**什么机制**做到（注册点、钩子、协议）？
2. **数据结构**是什么（谁是真相源、谁派生、谁拥有写入权）？
3. **边界**在哪（上限、并发、超时、权限）？
4. 会**怎么坏**（失效模式、静默降级、报错形态）？
5. **维护成本**多大（依赖宿主私有字段？文档滞后？没有测试？）？

坏答案长这样："用了 React 和 TypeScript。"——这不是机制，是语言。

好答案长这样："界面是插槽注册的；删除走宿主 `compaction/prune` + `surfaceOp:replace`；replace 对象必须是 3 个键；字段名硬编码，宿主改名即失效。"

## 对齐：两栏必须同时有话说

| 产品读法 | 开发读法 | 状态 |
|---|---|---|
| 有 | 有 | ✅ 可写进结论 |
| 有 | 无 | 回去读代码：要么没实现（标"无实现"），要么没找到（标"未验证"） |
| 无 | 有 | 回去用一遍：代码有这条路径，但用户碰不到，也是结论（"有但不可达"） |
| 无 | 无 | 不要写 |

## 翻译规则（双向）

**开发问题 → 产品后果**（翻译不出来就降权）：

| 开发事实 | 产品后果 |
|---|---|
| 6 个文件、零构建、零类型检查，硬编码宿主字段名 | 宿主小版本改名 → 删除按钮一点就 409，功能直接不可用 |
| 宿主 replace 原语不做 tool-pairing 校验 | 按类型筛选 + 全选 + 删除，两次点击就能切断调用与结果 |
| 只认 3/5 类事件，未知块计 0 token | 界面显示"system/message ≈0 token"，用户低估自己的上下文 |
| 折叠发生在宿主事件流之外 | 宿主侧仪表盘永远显示压缩前的构成，用户据此做出错误决策 |

**产品承诺 → 代码落点**（找不到就写"无实现"）：

| 产品承诺 | 需要找到 |
|---|---|
| "可调阈值 / 只看超阈值" | 阈值变量 + 持久化 + 过滤分支；找不到即"文档说谎" |
| "不改上下文顺序" | 只读投影 + 无排序写回；能验证 |
| "默认不用 iframe" | 无 `iframe` 创建；找到即"文档与实现相悖" |

## 三列核对（差集即价值）

| 宣称 | 可见 | 实现 | 结论 |
|---|---|---|---|
| 有 | 有 | 有 | 真实能力 |
| 有 | 无 | 无 | 文档谎言（最伤用户信任） |
| 有 | 有 | 无 | 不可持续（界面在演） |
| 有 | 无 | 有 | 不可达（有代码没入口，等于没有） |
| 无 | 有 | 有 | 未宣传的能力（值得写，常是隐藏价值） |

写报告时，**只有差集需要解释**。三列一致的，一句话带过即可。

## 失衡症状

- **只有产品镜头** → 写成用户评测：能判断"好不好用"，判断不了"会不会坏、值不值得抄"。
- **只有开发镜头** → 写成代码导览：能判断"写得怎么样"，判断不了"用户得到什么"。
- **两个镜头各写一半、互不引用** → 读者要自己做翻译，等于没分析。

## 判断落点

每条结论最后必须能回答一句：**"这对用户意味着什么？"**  
答不上来，就把它从结论区移到附录，或者删掉。
